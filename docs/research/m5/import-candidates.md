# M5 import candidates: Mutopia and PDMX

Research date: 2026-11-03. Everything here was fetched live: Mutopia's browse pages and PDMX's Zenodo record and `PDMX.csv`. No multi-GB archive was downloaded.

Machine-readable side files (in this folder):

- `mutopia-guitar.csv`: the whole Mutopia catalogue for Instrument=Guitar, scraped from `make-table.cgi` (40 pages). It has **395 pieces**, each with id, title, composer, opus, instrumentation, date, style, source edition, licence, .ly URL and .mid URL.
- `pdmx-guitar-subset.csv`: **926** PDMX rows. Every track is a GM guitar program, `license_conflict = False`, `all_valid` and `deduplicated`.
- `pdmx-folk-subset.csv`: **3,241** PDMX rows. These are single-track, `genres` contains `folk`, with no conflict and deduplicated.
- `fingering-prototype.mjs`: the working MusicXML → tab → alphaTex prototype (see `pipeline.md`).

## 1. Mutopia Project

### What is there

Top composers: Giuliani 90, Sor 75, Horetzky 60 (easy airs), Carcassi 39, Aguado 26, Bach 24, Knjze 18, Carulli 9, Mertz 9, Tárrega 6. A few modern pieces carry modern composers' own CC licences (Papezik, Olson, Burns, Brown). Gershwin's _Rialto Ripples_ is also listed (Gershwin died 1937, so it is PD in the EU, and it was published 1917, so it is PD in the US). All of these are fine to use, but none is beginner-relevant.

**Every licence on the listing is compatible with our content policy** (PD, CC BY, CC BY-SA). Imported files have to keep the source licence, not our CC0 arrangement licence. A Mutopia CC BY-SA typesetting stays CC BY-SA, with the typesetter credited (the `maintainer` field in the .ly header).

**Gaps.** Mutopia has no Sor Op. 31 or Op. 44 set, only 2 pieces of Carulli Op. 241 outside the "Guitar-Skole" set, and no Tárrega _Lágrima_. Use PDMX to fill these (section 2).

**Access.**

- **Per piece:** `https://www.mutopiaproject.org/ftp/<Composer>/<Opus>/<name>/<name>.ly|.mid`. Multi-file pieces ship as `<name>-lys.zip`; 13 of the picks below do.
- **Info page:** `cgibin/piece-info.cgi?id=<id>`.
- **Listing:** `cgibin/make-table.cgi?Instrument=Guitar&startat=<n>`, 10 rows per page.
- **GitHub:** the repo `MutopiaProject/MutopiaProject` holds the full .ly source tree. Anonymous `git clone` works through the session's git proxy. The GitHub REST API answered 403 because the repo is not attached to this session. Cloning was not needed, because the website gives everything.

### Conversion test (done in scratch, outside the repo)

| Path                                                                                                      | Result                                                                                                                                                            |
| --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.ly` → MusicXML via `python-ly` 0.9.10 (`ly musicxml`)                                                   | **Unreliable.** The Mutopia `copyright = \markup{…}` header crashes it, and variable-based scores (Sor Op. 60/1) come out with 0 notes. Giuliani Op. 50/1 worked. |
| `.mid` → MusicXML via **music21 10.5.2** → alphaTab `ScoreLoader.loadScoreFromBytes` → `AlphaTexExporter` | **Works on 4/4 pieces.** Sor 60/1 gave 16 bars, Giuliani 50/1 32, Carcassi 60/1 43 and Horetzky 1 20. Every result re-parsed as alphaTex.                         |
| + Viterbi fingering (`fingering-prototype.mjs`)                                                           | Assigns string and fret. Sor 60/1 and Giuliani 50/1 fit entirely within frets 0–5. Carcassi 60/1 has 9 onsets above fret 5, which is expected for that étude.     |

MIDI loses ties/tuplet spelling, articulation and the composer's fingering, and the octave is inconsistent: Mutopia MIDIs are either written or sounding pitch. The prototype auto-detects this and shifts by −12. So keep the `.ly` as the reference for the human reviewer: it often has string numbers (`\2`) and left-hand fingerings (`-1`).

- **Record:** https://zenodo.org/records/15571083 (v. 2025-06-01). The _dataset_ is published under **CC BY 4.0**: cite the PDMX paper, arXiv 2409.10831. The individual scores are tagged `publicdomain` (210,364) or `cc-zero` (43,713).
- **Code:** https://github.com/pnlong/PDMX. The Zenodo description links here. `speechprojects/PDMX` from the brief also returned 403 via the API, so neither repo was read.

### Metadata columns (`PDMX.csv`, 62 columns)

- **Paths:** `path` (data JSON), `metadata`, `mxl`, `pdf`, `mid`
- **Uploader and site:** `version`, `is_user_pro`, `is_user_publisher`, `is_user_staff`, `has_paywall`, `is_rated`, `is_official`, `is_original`, `is_draft`, `has_custom_audio`, `has_custom_video`
- **Popularity:** `n_comments`, `n_favorites`, `n_views`, `n_ratings`, `rating` (0–5)
- **Licence:** `license` (`publicdomain` | `cc-zero`), `license_url`, `license_conflict` (True when MuseScore's internal licence disagrees with the public one: 31,221 rows, 12.3 %)
- **Descriptive:** `genres` (hyphen-joined, e.g. `classical-soundtrack`), `groups`, `tags`, `song_name`, `title`, `subtitle`, `artist_name`, `composer_name` (free text, often with dates), `publisher`
- **Musical:** `complexity` (MuseScore's 0–2 difficulty tag; 919 of the 926 guitar rows are 0, so it is useless here), `n_tracks`, `tracks` (**hyphen-joined General-MIDI program numbers**, 0-based: 24 nylon, 25 steel, 26 jazz guitar, 0 piano), `song_length` (ticks), `song_length.seconds`, `song_length.bars`, `song_length.beats`, `n_notes`, `notes_per_bar`, `n_annotations`, `has_annotations`, `n_lyrics`, `has_lyrics`, `n_tokens`

- **Dedup:** `best_path`, `is_best_path`, `best_arrangement`, `is_best_arrangement`, `best_unique_arrangement`, `is_best_unique_arrangement`
- **Subset flags:** `subset:all`, `subset:rated`, `subset:deduplicated`, `subset:rated_deduplicated`, `subset:no_license_conflict`, `subset:all_valid`

### Filtering recipe

```python
# python -I filter.py PDMX.csv  (csv module; field_size_limit raised)
ok    = r['license_conflict'] == 'False' and r['subset:all_valid'] == 'True' and r['subset:deduplicated'] == 'True'
guit  = set(r['tracks'].split('-')) <= {'24', '25', '26'}
folk  = r['n_tracks'] == '1' and 'folk' in r['genres']          # single-melody folk tunes
pdera = composer_whitelist.match(r['composer_name'] + ' ' + r['title'])   # see below
```

1. **No licence conflict**, valid and deduplicated. Prefer `is_best_unique_arrangement`.
2. **Guitar**: every track is in {24, 25, 26}. For folk melodies, take a single track of any program and fingering is computed later.
3. **Musical PD check (essential).** The `publicdomain`/`cc-zero` tag is the _uploader's_ claim about the transcription, not about the work. The top-rated "guitar PD" rows include _Katyusha_ (Blanter, d. 1999), _Glory to Hong Kong_ (2019), _Happy Birthday_, _Petit Papa Noël_ (1946), a Charlie-Brown _O Tannenbaum_ arrangement and an a-ha arrangement. So keep a row only if `composer_name` resolves to a whitelist of composers who died before 1955 and published before 1930, or is "Trad./Anon./Volksweise". Then a human confirms it.
4. **Size and difficulty:** `song_length.bars` ≤ 64 and `notes_per_bar` ≤ 12 for L3–5. Then run our fingering pass: max fret ≤ 5 (L3), ≤ 7 (L4–5).
5. **Quality:** `rating` ≥ 4.3 with `n_ratings` ≥ 3, or `n_favorites` ≥ 5. Spot-check `scale_consistency` > 0.9.

**Usable estimate:**

- **~150–250 guitar pieces** survive steps 1–3; about 229 match the regex before removing false positives.
- **~40–80** of those are beginner–intermediate after step 4.
- For melody exercises, the folk subset yields roughly **1,000–2,000** single-line PD tunes once the same composer check runs. Most are "Trad.", but titles still need a sanity pass for modern songs tagged folk.
